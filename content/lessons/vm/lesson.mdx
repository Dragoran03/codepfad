C, C++ und Rust werden vorab in Maschinencode für einen bestimmten Prozessor übersetzt. Python und Java gehen einen Umweg: Sie übersetzen in **Bytecode** – Maschinencode für einen Prozessor, den es nicht gibt. Diesen gedachten Prozessor spielt ein Programm: die **virtuelle Maschine** (VM).

## Eine Maschine aus Software

Die meisten VMs sind **Stack-Maschinen**: Statt mit Registern rechnen sie mit einem Stapel. Das macht den Bytecode kompakt und leicht zu erzeugen – der Compiler muss sich nicht um die Verteilung auf Register kümmern.

## Interpreter, Bytecode, JIT

| Verfahren | Wie | Beispiele |
|---|---|---|
| **Baum-Interpreter** | läuft den Syntaxbaum direkt ab | frühe Skriptsprachen, Lehr-Interpreter |
| **Bytecode-Interpreter** | eine Schleife liest Befehl für Befehl und führt ihn aus | CPython, Ruby, Lua |
| **JIT-Compiler** | übersetzt heiße Stellen zur Laufzeit in Maschinencode | JVM (HotSpot), JavaScript-Engines (V8), .NET, PyPy |
| **AOT-Compiler** | übersetzt alles vorab | C, C++, Rust, Go, Swift |

Ein Bytecode-Interpreter ist im Kern eine riesige `switch`-Anweisung in einer Schleife: Befehl holen, verzweigen, ausführen, nächster Befehl. Jeder Python-Befehl kostet dadurch Dutzende Maschinenbefehle – der Hauptgrund, warum reines Python bei Rechenarbeit etwa 10- bis 100-mal langsamer ist als C. Bibliotheken wie NumPy umgehen das, indem sie die eigentliche Arbeit in C erledigen.

<Merke>

Eine virtuelle Maschine ist ein Programm, das so tut, als wäre es ein Prozessor. Dieselbe Idee steckt in WebAssembly (der Bytecode für Browser) und in der Ethereum-VM.

</Merke>
