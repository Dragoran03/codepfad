## Tabellen anlegen

`CREATE TABLE` legt eine Tabelle an. Jede Spalte bekommt einen Namen, einen Typ und optional Regeln (*Constraints*), über die die Datenbank wacht:

| Regel | bedeutet |
|---|---|
| `PRIMARY KEY` | eindeutige, nie leere Kennung jeder Zeile |
| `NOT NULL` | Pflichtfeld |
| `UNIQUE` | kein Wert darf doppelt vorkommen |
| `CHECK (…)` | jeder Wert muss die Bedingung erfüllen |
| `REFERENCES tabelle(spalte)` | Fremdschlüssel: Der Wert muss in der anderen Tabelle existieren |
| `DEFAULT wert` | Standardwert, wenn beim Einfügen nichts angegeben wird |

## Beziehungen

Zwischen Tabellen gibt es drei typische Beziehungen:

- **1 : n** – ein Kunde hat viele Bestellungen. Die „viele"-Seite bekommt den Fremdschlüssel (`bestellungen.kunde_id`).
- **n : m** – eine Bestellung enthält viele Produkte, ein Produkt steckt in vielen Bestellungen. Das braucht eine **Zwischentabelle** mit zwei Fremdschlüsseln – im Laden ist das `positionen`, die zusätzlich die Menge speichert.
- **1 : 1** – selten; oft gehören die Daten dann einfach in dieselbe Tabelle.

<Merke>

Regeln gehören in die Datenbank, nicht nur in den Programmcode. Programme haben Fehler, werden neu geschrieben und von mehreren Seiten aus benutzt. Eine `CHECK`-Regel in der Tabelle gilt für alle – immer.

</Merke>
