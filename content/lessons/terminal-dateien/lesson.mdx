Bevor es Fenster und Maus gab, sprach man mit Computern über Text: Befehl eintippen, Enter, Antwort lesen. Das **Terminal** (auch Konsole oder Kommandozeile) ist bis heute das wichtigste Werkzeug von Entwicklerinnen und Systemverwaltern. Server haben meist gar keine grafische Oberfläche, Build-Werkzeuge, Git und Paketmanager werden per Befehl gesteuert – und was man tippen kann, kann man auch automatisieren.

Das Programm, das deine Befehle entgegennimmt, heißt **Shell**. Auf Linux-Servern ist es meist `bash`, auf dem Mac `zsh`. Für alles in diesem Pfad verhalten sich beide gleich.

<Merke titel="Hier kannst du nichts kaputt machen">

Alle Befehle in diesem Pfad laufen echt – aber in einem frischen, abgeschotteten **Übungsordner**. Eine Sandbox verhindert, dass sie außerhalb davon etwas verändern oder ins Netz gehen. Auf deinem eigenen Rechner gibt es diese Grenze nicht.

</Merke>

`ls` kennt viele **Optionen**, die mit einem Bindestrich beginnen: `-l` zeigt Details wie Größe und Rechte, `-a` auch versteckte Dateien (deren Name mit einem Punkt beginnt). Optionen lassen sich kombinieren: `ls -la`.

## Anlegen, kopieren, verschieben, löschen

| Befehl | macht |
|---|---|
| `mkdir name` | Ordner anlegen (`-p` legt auch fehlende Zwischenordner an) |
| `touch datei` | leere Datei anlegen |
| `echo "Text" > datei` | Text in eine Datei schreiben |
| `cat datei` | Inhalt anzeigen |
| `cp quelle ziel` | kopieren (`-r` für Ordner) |
| `mv quelle ziel` | verschieben oder umbenennen |
| `rm datei` | löschen (`-r` für Ordner) |

<Merke titel="Vorsicht mit rm">

Es gibt keinen Papierkorb. Was `rm` löscht, ist weg. Und `rm -r` löscht ganze Ordnerbäume ohne Rückfrage. Prüfe vorher mit `ls`, was du löschen willst – vor allem, wenn Platzhalter wie `*` im Spiel sind.

</Merke>

Wenn du nicht weiterweißt: Fast jeder Befehl erklärt sich selbst mit `befehl --help` oder ausführlich mit `man befehl` (Handbuch; mit `q` beenden).
